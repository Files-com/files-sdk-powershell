# Set-FilesBehavior

## SYNOPSIS

Update Behavior.

## SYNTAX

### Id (Default)

```
Set-FilesBehavior [<parameters of the Id set>]
```

### InputObject

```
Set-FilesBehavior [<parameters of the InputObject set>]
```

## ALIASES

This cmdlet has no aliases.

## DESCRIPTION

Update Behavior.

The command accepts behaviors from the pipeline as -InputObject, and uses each one's Id and the connection that fetched it.

When given -InputObject, the command updates that object with the values Files.com returns and writes it.

The command supports -WhatIf, which describes the change without sending it to Files.com, and -Confirm, which asks before sending it.

File parameters take a FilesAttachment: a local file from Get-Item, such as (Get-Item ./logo.png), or one New-FilesAttachment makes from a file, bytes or a stream. The file goes in the same request as the other parameters, whose values are sent exactly as they would be without it; a local file is opened, and a stream read, only when the command goes ahead with the change: never under -WhatIf or when a confirmation is declined. A stream is borrowed: the command leaves it open.

## EXAMPLES

### Example 1: Update Behavior

```powershell
Set-FilesBehavior -Id 1 -Value @{ urls = @('https://example.com/webhook'); method = 'POST'; encoding = 'JSON' } -DisableParentFolderBehavior $true
```

Writes the behavior as Files.com returns it.

### Example 2: Act on behaviors from the pipeline

```powershell
Get-FilesBehavior -Id 1 | Set-FilesBehavior -Value @{ urls = @('https://example.com/webhook'); method = 'POST'; encoding = 'JSON' } -DisableParentFolderBehavior $true
```

Takes the behavior from the pipeline and uses its Id and connection.

### Example 3: Preview the change

```powershell
Set-FilesBehavior -Id 1 -Value @{ urls = @('https://example.com/webhook'); method = 'POST'; encoding = 'JSON' } -DisableParentFolderBehavior $true -WhatIf
```

Describes the change without sending anything to Files.com.
